## 标题

[BUG] markdown 在列表里嵌入表格的时候，修改表格的内容会删掉表格和列表内容之间的换行

## 标签

bug

## 问题描述

2022-11-18 由 huangcb01 报告，环境 OS: Windows / Linux，Extension Version: v2.9.0。

在 Markdown(WYSIWYG)中把表格嵌入列表项内部、表格与后续列表内容之间保留空行时，编辑表格单元格内容会导致空行被删除。报告者原话："当我修改表格第二行第二列的 2 时，表格跟"hello"之间的两个换行自动消失了。"

- 复现步骤(据正文整理)：
  1. 创建 Markdown 文件，在列表项内嵌入表格，表格后跟列表内容(如 "hello")，两者之间保留两个换行；
  2. 修改表格第二行第二列的单元格内容(值为 2)；
  3. 观察源文件。
- 正文附一张 GIF 演示(user-images 链接)展示问题发生过程，未以文本形式给出 Markdown 原文。
- 截至抓取时无任何评论，无维护者结论。

## 期望行为

编辑表格内容时，表格与后续列表内容之间的空行/换行保持不变，源码其余部分不被改写。

## 实际行为

编辑表格单元格后，表格与 "hello" 之间的两个换行被自动删除，内容挤到一起，列表结构被破坏(见正文 GIF 演示)。

# 问题确认及解决

## 复现数据

复现文件: `test-workspace/markdown/test-markdown-cweijan-157-list-nested-table.md`
生成脚本: 文本文件,直接维护

文件内容说明: 按 issue 语义最小化构造:一个列表项内嵌 3 列表格(2 行数据)，表格第二行第二列的值为 `2`(对应 issue 中被修改的单元格)；表格结束后与列表内容 `hello` 之间保留一个空行(两个换行符)，其后还有后续列表项。issue 未提供 Markdown 原文(仅 GIF)，嵌套缩进按常见列表内嵌表格写法构造。

### 复现步骤

1. F5 调起扩展调试，打开复现文件；
2. 在 WYSIWYG 视图中编辑表格：将第二行第二列的 `2` 改为其他值(如 `3`)，触发内容变更与自动保存；
3. 预期: 表格与 `hello` 之间的空行保持不变；实际: 表格与 `hello` 之间的两个换行被自动删除，内容挤到一起、列表结构被破坏。

## 根因定位

2026-10-05 静态核查(基于 fork 当前源码),问题链路:

- WYSIWYG 中编辑表格单元格 → vditor input 事件 → `VditorDOM2Md`(Lute)序列化输出规范化 markdown → 去抖保存链(`resource/markdown/index.js` 的 save → `updateTextDocument`)全文写盘;
- Lute 序列化做「无损语义但有损排版」的规范化,列表内嵌表格场景下,表格与后续列表内容之间的空行在规范化输出中丢失,并被直接写盘——即 issue 观察到的两个换行自动消失;
- 与 cweijan-596「保存静默改写」同一条保存链、同一类问题(596 处理了分隔线/表格重排/列表松散化等,本 issue 是其在「列表内嵌表格空行」上的具体表现)。

## 修复方案

**已随 cweijan-596 顺带解决**,无需单独改动:

- `30ae7da`(fix(cweijan-596))新增 `resource/markdown/styleRestore.js` diff3 风格还原:无用户编辑时字节级返回原文;有编辑时按行级锚点,未编辑区域还原原文写法,仅保留用户真实编辑;
- 表格与后续列表内容之间的空行属于未编辑区域,保存时被还原为原文;
- 该提交验证信息明确覆盖本场景:「模拟编辑后 save payload 除编辑行外与原文字节级一致(含表格空格行)」。

注:vditor 内存中 `getValue()` 仍为规范化输出(编辑期间如切换到源码模式可能看到空行消失),但写盘内容保真,issue 诉求(源文件空行不被删)已满足。

## 验证方式

- 静态核查结论:已修复(本项目 `30ae7da`,随 cweijan-596);
- 建议按复现步骤实测收尾:F5 打开复现文件,将表格第二行第二列 `2` 改为 `3`,等待自动保存后查看源文件,表格与 `hello` 之间空行应保留、其余内容与原文字节级一致。
